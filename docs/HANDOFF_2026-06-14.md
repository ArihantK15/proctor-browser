## 5. DECISIONS — chosen AND rejected, with why

- **Secret baking via `build/beforePack.js` (chosen)** over: afterPack (rejected — `asar:true` seals the code before afterPack runs, so it can't modify source) and a `build.yml` pre-step (rejected — more invasive matrix edits, easier to get wrong per-platform). beforePack runs inside electron-builder on every platform with the build env present.
- **Plaintext baked secret in the asar (accepted)** over bytenode-by-default (rejected *for now* — bytenode is platform/arch-specific, highest-risk-to-break, and I couldn't test a packaged build locally; shipping it untested into a security release was worse than a plaintext secret that's already within the accepted threat model). Revisit on the next release.
- **Enforcement OFF by default (chosen).** Ship the code dark, flip later. Turning on a "block the user" gate is a product/timing call, not a code call — it 403s live exam-takers if adoption/secret/clock aren't right, and that's unrecoverable in the moment.
- **Did NOT wire Electron Fuses myself** — I initially flagged "Fuses not wired" then found they're already in `package.json` → `electronFuses` (incl. `resetAdHocDarwinSignature: true`, the v2.3.9 re-sign fix). Corrected my own wrong finding.
- **semver leniency (chosen):** `_semver_gte` (`app/services/kiosk_attest.py`) takes the leading integer of each dotted part, so `2.4.0-beta` compares as `2.4.0` instead of collapsing to `(0,0,0)` and being wrongly rejected.
- **Discarded the #25 breach-notification work twice** — DeepSeek kept re-implementing a `breach_notifications` table/router that **already exists** as `breach_incidents` (migration `phase103`, fuller feature). #25 was already done; the duplicate would have created two parallel breach systems.
- **Discarded a duplicate `@sparticuz` prerender fix** — another agent re-implemented the Vercel Chromium fix I'd already shipped to main; kept main's version.
- **Honest scope on client attestation:** rejected hardware attestation (TPM / Apple App Attest) as out-of-scope/expensive. Accepted that client attestation is bypassable by a reverse-engineer (extractable secret) — it raises the bar against casual bypass only. The real backstop against a determined cheater is the AI proctoring + human review, not this.

## 6. FRAGILE / KNOWN-RISK (be specific before you touch these)

- **Cross-language canonical drift.** `lib/attestation.js` `canonicalJSON` must byte-match `app/services/kiosk_attest.py:22` `_canonical` (`json.dumps(sort_keys=True, separators=(",",":"))`). Verified identical **for ASCII only**. Python defaults `ensure_ascii=True` (escapes non-ASCII as `\uXXXX`); JS `JSON.stringify` does NOT. If any attestation field (`roll`, `platform`, `client_version`) ever contains non-ASCII, the HMAC silently breaks → 403. Not currently exercised, but a non-ASCII roll number would do it.
- **Secret bake is line-format-sensitive.** `build/beforePack.js` string-matches the quoted placeholder `'__KIOSK_ATTESTATION_SECRET__'` on `lib/attestation.js:7`. Reformat/relocate that line and the bake fails. There IS a guard (beforePack throws if a secret is set but the placeholder is gone), but a reformat that keeps the token in a different quote style could slip past.
- **Attestation enforcement path is untested against a real client+server** (see §3). The unit tests prove the crypto, not the deploy.
- **Heartbeat re-attestation is not session-bound.** `app/routers/exam.py:~1048` calls `verify_attestation(hb_att, hb_sig)` with no `session_key`/nonce — it only flags `kiosk=false` and accepts any validly-signed payload. Low risk (needs the secret to sign), but not bound to the session.
- **Paginated stream bug class.** I fixed the #40 CSV infinite-loop in `app/repositories/sessions.py` `stream_csv_results` (mock `.range()` doesn't truly paginate, so the bug passed unit tests). Other paginated stream paths could hide the same bug; mocked tests won't catch it.
- **`requirements.lock` stash** (see §7) — uncommitted dependency-lock churn from another session that could matter for reproducible builds.

## 7. GOTCHAS — look wrong but intentional; don't "fix" these

- **`build/afterPack.js` map-strip on `Contents/Resources/app` is DEAD CODE under `asar:true`** (the code lives in `app.asar`, not a dir). Harmless. Maps are already excluded via `package.json` `build.files` (`!**/*.map`). Don't expect it to do anything.
- **`afterPack.js` deliberately does NOT `codesign` the outer `.app`** (only the bundled Python). Pre-fuse signing is exactly the v2.3.9 bug that SIGKILL'd every student Mac ("Code Signature Invalid"). electron-builder seals the bundle AFTER the fuse flip via `electronFuses.resetAdHocDarwinSignature`. **Never add `codesign --deep` of the .app here.**
- **`verify-macos-build.mjs` is the real build gate; `npm test` is a static linter, not proof.** This repo signs ad-hoc only (no Developer ID / notarization) — macOS shows "unidentified developer", not "damaged". That's expected.
- **Postgres write layer: never `{"col": "now()"}`.** The literal string `"now()"` is sent as a param to a `timestamptz` → asyncpg `DataError`. Only ISO-8601-prefixed strings are coerced to datetime. Use `datetime.now(timezone.utc).isoformat()`. (Bit gap #24; mocked tests don't catch it.)
- **Don't name JSON-response dict keys `_sa*`.** FastAPI's `jsonable_encoder(sqlalchemy_safe=True)` silently strips any key starting with `_sa` — that's why `_sandbox` was renamed `_is_sandbox` in `app/services/billing.py`/`app/routers/billing.py`. A response field like `_safe_mode` would vanish.
- **`require_admin` 403s a superadmin on ALL mutations** except paths in `_SUPERADMIN_WRITE_ALLOW` (`app/auth/admin_auth.py`). A new superadmin-only POST/PATCH endpoint is dead-on-arrival unless its path prefix is added there (this bit #35 coupons). Dashboard mirror: superadmin must be dropped from tenant-product tabs in `dashboard.html`.
- **CSP is `script-src 'self'`, no inline scripts** (`app/main.py:582`, enforced not report-only, applies to every response). Every server-rendered HTML page must use external `/static/*.js` + `data-*`/`addEventListener`. Inline `<script>` renders but silently does nothing in prod. This bit reset-password, org-invite, status, classroom, LTI.
- **`docs/GAP_ANALYSIS_2026-06-12.md` is STALE and misleading** — many "open" gaps are done; some "done" ones were broken (#16 cache existed but was dead). Trust `docs/GAP_AUDIT_2026-06-14.md` instead.
- **Mocked unit tests pass against stubs that don't reflect real Postgres types, JSON shapes, or pagination.** Green unit ≠ working. Use the CI integration leg and read the actual data flow. This single fact is behind most bugs found this session.
